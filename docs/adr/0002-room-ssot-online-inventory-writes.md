# Room 作为读 SSOT，库存写在线优先

状态：已接受（2026-10-25）

仓库现场网络不稳定，但库存数据的正确性优先于离线可用性。若允许离线写入并在之后合并，需要处理冲突、幂等、顺序与重复提交，复杂度远超 MVP 范围。因此读路径以 Room 为唯一数据源：网络同步只负责把服务端数据写入 Room，页面观察 Room；所有会改变库存的写操作（入库、出库、盘点）必须在线提交并由服务端确认，客户端不做乐观库存扣减，也不维护离线写队列。

## 考虑过的选项

- 纯在线、无本地缓存：实现简单，但弱网下页面不可用，列表反复转圈。
- 完整离线优先（本地写队列 + 同步）：现场体验最好，但需要冲突解决与服务端幂等契约，当前不具备条件。

## 后果

- 同步触发点固定为启动、进入页面与手动刷新；MVP 不接 WorkManager 定时同步。
- 同步失败保留旧数据并展示刷新失败，不清空缓存。
- 离线写队列是明确的后续演进项，不是被遗忘的需求。
