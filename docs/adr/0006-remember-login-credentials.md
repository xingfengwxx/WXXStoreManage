# 记住登录凭据

状态：已接受（2026-10-25）

登录成功后，如果用户保留默认勾选的“记住账号密码”，客户端把账号与密码保存到本机，下一次进入登录页时回填；它只回填表单，不代表自动登录，也不延长服务端会话。凭据整体以 Android Keystore 的 AES-GCM 加密（复用 `SessionCipher` 的密钥），密文写入独立的 `credential_store` DataStore；备份与设备迁移规则必须排除该文件。用户取消勾选并登录成功后，清除已保存的凭据，并把“不记住”这一非敏感偏好持久化，避免下次登录重新默认勾选。

只有登录成功（服务端认证通过、拿到 JSESSIONID 且会话写入成功）后才更新凭据；凭据写入失败不回滚登录，只记录不含密码的失败日志。读取失败或密文损坏按“未记住”处理并删除坏数据。登录页异步回填时，如果用户已经开始输入或提交，则放弃回填，避免覆盖用户输入。登出与会话失效不清除记住的凭据。

## 考虑过的选项

- 只记住账号、不保存密码：安全风险最低，但不满足退出后免输入密码的诉求。
- 明文保存到普通 DataStore / SharedPreferences：实现简单，但设备被读取或备份泄漏时等同于泄露账号密码。
- 使用系统 Autofill / Credential Manager：不落盘自有密码，但依赖系统 UI 与用户授权，无法保证页面内回填。
- 保存密码用于自动登录：体验更省事，但把“记住凭据”升级为长期有效的登录态，超出当前需求，也让退出登录失去意义。

## 后果

- [ADR-0005](0005-session-persistence-optimistic-restore.md) 中“不保存 password”的约束由本决策修订：密码现在会以密文形式留在本机，只用于登录表单回填。
- 安全边界仍依赖设备与 Keystore：已 root、Keystore 被攻破或应用进程被调试时，密码可能被解密；这是“记住密码”相对只记住账号的固有代价。
- 凭据 DataStore 必须继续排除在云备份与设备迁移之外；Keystore 密钥不随备份迁移，恢复后的密文本来也无法解密。
- `CredentialStore` 是凭据的唯一入口；feature 只能拿到回填用的账号密码与勾选偏好，不接触密文、DataStore 文件或 Keystore。
