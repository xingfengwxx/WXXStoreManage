# WanAndroid 作为临时认证源

状态：已接受（2026-10-25）

本项目的目标后端是自建仓储服务，但该服务与角色体系尚未实现。为了在不等待后端的前提下打通「登录 → 会话 → 启动门禁 → 退出」的完整链路，决定暂时使用 WanAndroid 开放 API 的 `POST /user/login` 校验用户名与密码。认证能力收敛在 `AuthRepository` 之后：feature 只依赖「当前用户」与会话状态等领域模型，不接触 WanAndroid 的接口、DTO、cookie 或响应中的 `admin` 字段；后续替换为自建后端时只替换数据层实现。

WanAndroid 登录只建立身份与会话，不产生本项目所需的管理员/仓管员角色。响应中的 `admin` 是玩Android 站内管理员标记，不是仓储业务角色，禁止映射。本迭代不实现任何基于角色的授权判断。

## 考虑过的选项

- 等待自建后端：领域模型最干净，但登录功能无法端到端验证。
- 本地假登录（任意账号密码通过）：零网络依赖，但无法验证真实认证、错误映射与会话持久化。
- 把 WanAndroid 作为长期账号体系：可直接复用其账号，但它没有仓储业务角色，也无法承载库存与单据接口。

## 后果

- `AuthRepository` 的实现、接口与 DTO 属于临时设施；替换后端时连同会话凭据一起替换。
- 登录失败 `errorCode == -1` 映射为 `AuthenticationFailed`，`-1001` 映射为 `SessionExpired`，其他非 0 映射为 `Unknown` 并保留 `serverCode`。
- 角色授权在自建后端接入前保持未实现；UI 不展示角色，也不推测权限。
- 「服务端必须校验权限」的约束不变，只是当前没有可校验的业务接口。
